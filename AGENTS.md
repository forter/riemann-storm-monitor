## Repository Overview

[PUBLIC REPO] riemann-storm-monitor is a Java library that acts as a Riemann agent, providing various useful tools for monitoring Storm topologies. It focuses on:

- Wrapping Storm bolts and spouts for monitoring
- Measuring events and functions throughput
- Monitoring bolt and spout latency

Key features:
- MonitoredBolt and MonitoredSpout wrapper classes
- EventsAware interface for custom event tracking
- Automatic latency monitoring

This library is designed to work with Apache Storm and Riemann for comprehensive topology monitoring.

**Tech Stack**: Java, Apache Storm, Riemann

## Critical Patterns

1. Wrapper Classes:
   - Use `MonitoredBolt` and `MonitoredSpout` to wrap your existing bolts and spouts for monitoring.

2. Topology Definition:
   ```java
   TopologyBuilder builder = new TopologyBuilder();
   builder.setSpout("testMockSpout", new MonitoredSpout(new MockSpout()), 1);
   builder.setBolt("testMockBolt", new MonitoredBolt(new MockBolt()), 1).localOrShuffleGrouping("testMockSpout");
   ```

3. EventsAware Interface:
   - Implement `EventsAware` in your bolt/spout classes to enable custom event tracking.
   - Use the `setEventSender` method to receive an `EventSender` instance.
   - Call `es.sendEvent()` to send custom events.

4. Configuration:
   Set these values when initializing the topology:
   ```java
   conf.put("topology.monitoring.latencies.map.maxSize", 500);
   conf.put("topology.monitoring.latencies.map.maxTimeSeconds", 120);
   conf.put("topology.monitoring.latencies.map.maxConcurrency", 4);
   ```

## Common Pitfalls to Avoid

1. Forgetting to wrap bolts/spouts with `MonitoredBolt` and `MonitoredSpout`.
2. Not implementing `EventsAware` when custom event tracking is needed.
3. Overlooking the configuration of latency map parameters, which may lead to suboptimal monitoring.
4. Misusing the `EventSender` by sending too many events, which could impact performance.
